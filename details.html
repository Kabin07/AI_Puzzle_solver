Objective: understand state-space search by building an interactive web application that solves the 8-puzzle and visually shows how the assigned algorithm, Greedy Best-First Search, searches for the goal state. It is implemented from scratch in JavaScript.

The 8-Puzzle Problem

The 8-puzzle is a 3×3 board with eight numbered tiles and one blank square. A tile next to the blank can slide into it. Starting from an initial state, the goal is to find a sequence of moves that reaches the goal state. It is a classic example for studying state-space search because it is small enough to search completely but large enough to show clear differences between algorithms.

Problem formulation

StatesAny arrangement of tiles 1–8 and the blank on the 3×3 grid (9! = 362,880 arrangements).
Initial stateEntered by the user or generated randomly (always solvable).
ActionsMove the blank Up, Down, Left or Right. Only 2–4 moves are legal, depending on where the blank is.
Transition modelSwap the blank with the neighbouring tile in the chosen direction.
Goal testThe current state equals the goal state.
Path costEvery move costs 1, so path cost g(n) = number of moves.

Key facts

  • Reachable states: 9!/2 = 181,440. The arrangements split into two halves that can never reach each other.
  • Solvability: count the inversions (pairs of tiles in the wrong order, ignoring the blank). A puzzle is solvable when the start and goal have the same inversion parity. The app checks this before every run.
  • Branching factor: 2, 3 or 4, about 2.67 on average.
  • Hardest instances need 31 moves. Random solvable puzzles need about 22 on average.
How to Use the Application

Puzzle Solver

  1. Enter the puzzle in the two 3×3 grids. Type digits 1–8 and use _ (or leave a cell empty) for the blank. You can also type a whole state in the text box below each grid, e.g. 2 8 3 1 6 4 7 _ 5. Arrow keys move between cells.
  2. Or click Generate Random Puzzle (Easy, Medium, Hard or Fully random). Generated puzzles are always solvable.
  3. Choose the heuristic. The solver uses Greedy Best-First Search; pick Manhattan Distance or Misplaced Tiles as h(n).
  4. Press Run. The search plays back one expansion per step, then the solution path is animated move by move.
  5. Read the panels: current node and parent, generated successors (green = added, grey = already explored, yellow = already in the frontier), the Open and Closed lists, the h(n) / depth chart, then the Solution Summary and Final Solution Path.

Heuristic Comparison

  1. The puzzle last used in the Solver is loaded automatically, so both pages work on the same instance.
  2. Choose how many random puzzles to include in the batch test, then press Run Comparison.
  3. Read the same-puzzle table (GBFS with Manhattan Distance vs Misplaced Tiles), the four charts, the batch averages and the observations. Use Download results (CSV) to save them.

Algorithm Description

Use the menu on the left to jump between GBFS's description, the worked example, the heuristics and the theory overview. The Try GBFS in the solver button opens the Solver.

Getting around

  • The menu bar at the top is the same on every page; the logo always returns to Home.
  • Inner pages show a breadcrumb, numbered section steps (1 Solver → 2 Comparison → 3 Algorithm → 4 Details) and a Back to Home button.
  • At the bottom of each page, Previous / Next section cards lead through the sections in order.
  • The button switches between light and dark mode.
